# Open questions

Status: Draft · 2026-11-07

## Still open

A decision the docs do not settle is added here, with the default the plan assumes until
the owner answers it. Until M2 closes, work goes on with that default, unless the choice is
security-sensitive or hard to reverse (decided below). Numbers are not reused: the next question
is 17.

| # | Question | Why it matters | Default assumed | Needed by |
| --- | --- | --- | --- | --- |
| 13 | How the GitHub connector learns which GitHub App it is, and which installation | A connection had one secret and nowhere for an app's ID, and an installation's ID is one more value for an admin to find and keep right | **`spec.credentials.appId` holds the app's ID, in the document since it is public, and `spec.credentials.ref` the private key.** The installation is found from them (`GET /repos/{owner}/{repo}/installation` with the app's JWT, checked on the sandbox), kept in memory, and looked up again after GitHub refuses a token. Tokens are limited to the connection's one repository, whatever the app is installed on ([GitHub](../design/12-git-connectors.md#github-second)). The wizard asks for the app's ID since P3-18 | GA |
| 14 | What makes the definitions trusted on GitHub: a `CODEOWNERS` rule covering `.quai/`, a branch rule requiring code owners' review, or both ([#131](https://github.com/damhau/quai/issues/131) reads "`CODEOWNERS`, or rulesets requiring code owner review") | On GitHub, `CODEOWNERS` alone only requests reviews, so anyone who may approve can merge a change to `.quai/`; a rule requiring code owners' review alone requires nothing of `.quai/` unless `CODEOWNERS` covers it | **Both**: `CODEOWNERS` covering `.quai/` (read as GitHub reads it), and the branch requiring code owners' review in a ruleset or branch protection; each missing part is a trust problem ([trust](../design/01-repository-connections.md#trust)). Accepting either would show an untrusted repository as trusted | GA |
| 15 | How GitHub's webhooks reach Quai: a webhook on each repository, or the GitHub App's own webhook | The app's webhook is one URL and one secret for every repository the app is installed on, while Quai's endpoint is per connection (`/webhooks/<name>`) and verifies with the connection's own `spec.webhooks.secret`. A repository webhook needs the app's Webhooks (read and write) repository permission, or an admin to add it by hand | **A repository webhook per connection**, at `/webhooks/<name>` with `spec.webhooks.secret`, installed by `Subscribe` when the app has the Webhooks permission, otherwise added by hand as the health page says ([GitHub](../design/12-git-connectors.md#github-second)). The app's own webhook is not used. The connector parses its deliveries the same way and drops another repository's, so an app-wide route, fanning one delivery out by repository, can be added later without changing the connector | GA |
| 16 | How the pull requests people open themselves (a new type in `.quai/`, a Terraform module, a pipeline) merge on a branch that requires `quai/approval` | The status check applies to every pull request, with no path filter, and only Quai's identity may post it ([Azure DevOps](../design/12-git-connectors.md#azure-devops-first-services-then-server)); Quai posts it only on its requests' pull requests. So once a repository is onboarded, no one's own pull request completes without a policy bypass: on `pilot-infra`, P3-19's pull requests !407 to !410 passed their build validation (runs 173 to 176) and wait on it | **The platform owners complete them with a policy bypass**: Azure DevOps' "Bypass policies when completing pull requests" (GitHub: a ruleset bypass entry), given to their group only, after the `/.quai/*` reviewers approve. Quai's identity never has it, so `quai/approval` still binds Quai, and no one posts `quai/approval` by hand on a pull request Quai did not open: that would be an approval Quai never gave. Quai reviewing such pull requests under rules of its own would be Phase 4 work | P3-19 (#133) on `pilot-infra`; every repository onboarded after its status check |
